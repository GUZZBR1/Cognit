# TrialRecord v1

TrialRecord v1 is an isolated per-attempt contract. Each attempt has a `session_id` and may carry a pseudonymous `participant_id`. Input IDs must use opaque prefixes and lowercase hexadecimal tokens; manifest versions use `major.minor.patch`. None may encode personal information. Every export requires `TRIAL_RECORD_PSEUDONYM_KEY` with at least 32 characters. The exporter replaces trial/session/challenge/seed/manifest/participant IDs with deterministic HMAC-SHA-256 pseudonyms scoped to the manifest's `study_id`; the key is never included in output. Study/protocol, build, environment, and run configuration remain referenced at manifest level; this record does not copy issue #45's study-level metadata into every attempt. Manifest challenge membership is an exact array reference, and the attempt config hash must match the manifest. The JSON Schema is `schemas/trial-record-v1/schema.json`.

`actor` describes the observed actor class. Labels are restricted actor-specific categories and accepted only with supported, actor-compatible provenance plus `independent: true` and `valid: true`. `UNKNOWN` is retained with a null label. Risk scores, predictions, policy outputs, and `protected_action_reached` belong under `outcome.observations`; risk scores are finite values from 0 to 1 and prediction/policy values are bounded labels. These are measurements, never ground truth. `protected_action_reached` accepts `true`, `false`, `null`, or absence; null/absence mean `UNKNOWN`. Explicit booleans require sibling `protected_action_reached_provenance` with `trial_id`, `source`, `method`, `origin`, and `observed_at`; the trial ID must identify this exact record. Export pseudonymizes that provenance ID consistently with the record ID. The observation says whether an outcome was observed and does not identify the actor.

`oracle_access` is required and records access explicitly. Oracle-assisted rows are only unlabeled automation or agent controls with `evidence_class: oracle_assisted`; QC rejects oracle-access rows carrying a label, and the schema encodes the same exclusion. Such rows must never be included in perceptual ground-truth sets.

The local CLI verifies required fields, unique trial IDs, opaque identifiers, semver manifest references, the manifest's canonical-content SHA-256, exact challenge membership, provenance, label constraints, oracle exclusion, real UTC calendar timestamps, timing consistency, and bounded observation values. It emits deterministic JSONL: a header with contract version, optional `source_evidence_class`, SHA-256 of accepted records sorted by session and trial ID, a QC report with accepted/rejected counts and rejected row IDs/reasons, and an `envelope_hash`, followed by accepted rows only. Exports for the experimental benchmark pipeline also include the validated canonical Trial Manifest reference. The envelope hash is SHA-256 over canonical JSON of the complete header except the hash field itself, binding every present header field, including the manifest reference when supplied, evidence declaration, QC report, and row-artifact digest. It detects accidental or unauthorized content changes only when the hash is not recomputed; it is not a digital signature, does not authenticate the exporter or observer, and does not prove that an observation occurred. `source_evidence_class` is copied from the manifest when it is `SIMULATED`, `OBSERVED`, or `REPLAYED`; report consumers do not treat `OBSERVED`/`REPLAYED` declarations as proof. Rejected rows are omitted and the CLI exits with status 1 when any row is rejected. Contact fields, arbitrary top-level fields, unrelated observation keys, and trajectories are omitted from output. Inputs may include adapter-only extra fields; the JSON Schema describes the minimized canonical row. The manifest digest is SHA-256 over canonical JSON after removing its `sha256` field. An output path that resolves to the input or manifest is rejected.

```sh
TRIAL_RECORD_PSEUDONYM_KEY='replace-with-a-secret-of-at-least-32-characters' node scripts/trial-record.mjs --input fixtures/trial-record-v1/records.json --manifest fixtures/trial-record-v1/manifest.json
TRIAL_RECORD_PSEUDONYM_KEY='replace-with-a-secret-of-at-least-32-characters' node scripts/trial-record.mjs --input fixtures/trial-record-v1/invalid.json --manifest fixtures/trial-record-v1/manifest.json
npm run test:trial-record-v1
```

The included fixture dataset and its manifest are simulated local examples. They are not production observations, a benchmark result, or evidence of model performance. Validation/export needs no producer, database, or network. Provenance source categories and independent/valid declarations are checked structurally; the CLI does not authenticate an external observer or turn fixture assertions into measured evidence.

For the deterministic fixture-only TrialRecord-to-benchmark pipeline, its canonical Trial Manifest link, and tri-state session aggregation, see [Experimental pipeline readiness v1](experimental-pipeline-readiness-v1.md). The research pipeline is maintained in `main` but remains outside the production SDK package.

Keep the 32-character-or-longer key outside the repository and never commit or print it. The value shown above is an instruction placeholder, not a production secret.
